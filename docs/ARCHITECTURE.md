# Architecture

Sand Burst Magic follows the structure of Block Burst Magic and Water Sort
Magic: the rules are plain Dart with unit tests, services wrap every plugin,
state classes sit between them and the UI, and all text lives in
`lib/l10n/strings.dart`.

```
lib/
  main.dart, bootstrap.dart   splash (held 1.5 s), loading saved data, services
  app.dart                    MaterialApp, lifecycle (flush saves on pause)
  app_info.dart               name, IDs, links (configurable with --dart-define)
  core/                       rules, no Flutter imports
    rng.dart                  mulberry32 + FNV-1a string hash (same as Python)
    sand.dart                 board, cells, shapes, sand settling, row bursts,
                              special sand, obstacles, scoring, layouts
    engine.dart               game config, dealing, turns, power-ups, bot
    levels.dart               worlds, campaign catalogue, modes, daily puzzle
    level_data.dart           GENERATED by tool/reference_model/gen_levels.py
    progression.dart          coins, power-up shop, cosmetics, missions,
                              achievements, daily streak, statistics
    engagement.dart           rating prompt, reminders, interstitial policy
  data/                       key-value store, versioned JSON documents, models
  services/                   storage, audio, haptics, ads, purchases, share,
                              review, reminders
  state/                      AppServices, ProgressController, GameController,
                              Launcher, SettingsController
  ui/
    game/board_fx.dart        animation timeline + particle pool
    game/sand_painter.dart    the board, grains, specials, obstacles, previews
    screens/                  home, game, campaign, modes, shop, stats,
                              tutorial, settings, welcome, sheets, results
    share/                    result card image and share action
    widgets/, theme/          shared widgets, tokens, sand palettes, boards
```

## The rules (`core/`)

The board is a 10 × 10 grid of `Cell?`. A cell is either a grain-cell of
sand (colour + kind) or an obstacle. Each cell has a stable `id`, so the UI
can follow a grain as it falls.

**Placing** writes the piece's cells into empty, placeable cells, then
`_resolve` repeats until nothing changes:

1. `settle()` – synchronous steps. In each step every movable grain (bottom
   row first, alternating sweep direction) falls straight down if the cell
   below is free (or a sand trap), otherwise slides diagonally if the side
   cell and the diagonal cell are free. Heavy and sticky sand never slide;
   frozen sand, sticky sand and its neighbours never move. Traps swallow
   grains and turn into packed sand after three. Each step is recorded.
2. `fullRows()` – a row is complete when every cell holds sand or an
   obstacle (an open trap blocks it).
3. `clearWave()` – removes the rows (stone and crystal walls lose a hit
   point, locks count down, unbreakable blocks stay), triggers explosive /
   volcanic / magnetic sand in a queue, breaks ice and thaws frozen sand next
   to the rows, and scores the wave (`wavePoints`: row base × combo × chain).

Then sticky timers tick and moving barriers slide, each followed by another
resolve. Chain reactions are processed safely (at most 30 waves a turn) and
a row can only clear once per wave. Status is updated: objectives met → won;
move limit → lost('moves'); nothing in the tray fits → lost('space').

**Dealing** draws three shapes by weight, a palette colour and possibly a
special kind (level table, or the Classic / Endless score schedule), from the
game's own RNG state. If no dealt piece fits but some shape would, the first
piece is replaced by the largest shape that fits.

**Power-ups** (`power()`) remove a row / a colour / a 3×3 area / a colour
group, shuffle loose grains, fill a nearly complete row with grey frozen
sand, shift gravity sideways, or add a bonus single block. Each returns null
(and changes nothing) when it would have no effect.

**The bot** (`bestMove`) tries every placement (highest and lowest row in
each column for each piece), plays it on a copy and scores the result
(objective progress, height, holes, score; nearly full rows when the goal is
multi-row bursts). It gives hints, generates daily targets and proved the
campaign.

### Python reference model

`tool/reference_model/core.py` is the written specification. `content.py`
describes the 100 levels; `gen_levels.py` turns each into a concrete level
(seed, settled starting board, move limit, stars) by trying seeds until the
bot wins, and stores the winning moves. `gen_vectors.py` records random
numbers, layouts, four whole bot games and every power-up; the Dart tests
must match all of it exactly.

## Levels and modes

`LevelCatalog` parses `level_data.dart`. Worlds: 1–17, 18–34, 35–51, 52–68,
69–84, 85–100. Move limits are the bot's moves × 1.8 (world 1) down to × 1.4
(world 6) + 2. Stars: 3 for at most par × 1.15 moves, 2 for par × 1.6 + 2.

`Modes` builds Classic, Endless, Time Challenge and Limited Moves configs.
`DailyPuzzle.generate(date)` seeds everything from the date: a world palette,
a special sand, a layout (`makeLayout`, same algorithm as Python) and a goal
type; the bot plays it to measure what is reachable in 25 moves, the target
is set to 60 % of that, and the bot must then win the real puzzle (the goal
is lowered until it does). Generation runs in a background isolate and the
result is cached for the day.

## State

`GameController` owns one game: it calls the engine, records the last
`Turn` for the animation, saves after every move (one saved game per mode),
handles hints and undo (one free each, more after a rewarded ad), the Time
Challenge clock, "Keep playing?", results (`ProgressController.recordGame`),
interstitial timing and the rating prompt.

`ProgressController` owns coins, inventory, cosmetics, level records,
daily record, missions, achievements and statistics; it saves 0.4 s after a
change (play time is saved with the next change, never every second).

## Rendering

`BoardFx` keeps a *shown* board. A turn is replayed phase by phase from the
engine's record: the placed block appears and dissolves into grains, each
settle step moves grains for 24 ms, a wave glows and bursts into particles,
movers slide, traps fill. At the end the shown board is replaced by the
real one. Input is blocked until the turn has finished animating, and the
tray shows the new set only then.

`SandBoardPainter` draws every grain-cell as 5 × 5 grains with jitter based
on the cell id (so a cluster keeps its look while falling). Grains are
batched by colour and shade and drawn with one `drawRawPoints` call per
batch. Special sand and obstacles get small overlays; rainbow sand cycles
colours. Burst particles live in a fixed pool of 700 (typed arrays, no
allocation per frame). Reduce motion speeds animations up and shrinks
bursts.

## Saving

Every document is versioned JSON in SharedPreferences (`DocStore`): settings,
progress, one saved game per mode, the cached daily puzzle, ad and review
state. Malformed data is backed up and replaced with defaults; newer-version
data is never overwritten.
